# 建图算法详解与调试指南

> 对应代码: `src/bomb/coordinateMapper.cpp`, `src/bomb/bombDropSystem.cpp::scanForTargets()`

---

## 一、算法流程

```
┌─ SCAN 阶段 (无人机在 searchAlt=3.5m 悬停) ───────────────────────┐
│                                                                 │
│  each 100ms:                                                     │
│    1. 读取 pipe → multiBucketData (每帧多桶, 变长二进制协议)        │
│    2. 像素空间聚类 (50px 半径)                                    │
│    3. 簇稳定跟踪 → 3帧稳定后映射世界坐标                           │
│    4. 世界坐标边界检查 (±20m) → 去重(0.5m) → bucketId 投票 → 加入目标地图│
│    5. 扫描结束时按评分排序 (尺寸 + 优先级)                          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.1 像素聚类 (替代 YOLO 标签跟踪)

**为什么不用 YOLO 标签建图**：YOLO 在高空会对不同物理桶误分类为同一 bucketId，导致按标签跟踪时：
- 两个桶被合并成一个 → 丢失目标
- 同 ID 的像素位置剧烈跳变 → 稳定计数器反复重置，无法建图

**聚类算法** (greedy single-linkage):
```
for each frame:
    for each detection (bucketId, cx, cy):
        找最近的已有簇 (距离 < 50px)
        ├─ 找到 → 加入该簇
        └─ 未找到 → 新建簇
    更新每个簇:
        中心 = 本帧所有分配检测的均值
        稳定帧数++ (若中心变化 < 50px)
        bucketId 投票累计
    稳定 ≥ 3帧 → 簇中心映射世界坐标 → 加入地图
    未匹配簇 → 删除
```

**关键参数**:
- `CLUSTER_RADIUS = 50` 像素 — 同一物理桶在不同帧的像素位置变化容差
- `STABLE_FRAMES = 3` — 需要连续3帧稳定才确认

### 1.2 像素→世界坐标映射 (`pixelToWorld`)

核心数学原理：**针孔相机模型 + 地平面求交**

```
Step 1: 像素归一化
    xn = (u - cx) / fx
    yn = (v - cy) / fy
    r_cam = [xn, yn, 1]^T    (相机坐标系射线)

Step 2: 相机系 → 机体系
    R_c2b = [[0,1,0], [1,0,0], [0,0,1]]
    (Xc=右 → Yb=右, Yc=下 → Xb=前, Zc=前 → Zb=下)
    r_body = R_c2b × r_cam

Step 3: 机体系 → NED世界系
    R_b2n = eulerToRotation(roll, pitch, yaw)
    r_ned = R_b2n × r_body

Step 4: 相机偏移补偿
    cam_ned = drone_ned + R_b2n × camera_offset

Step 5: 地平面求交
    ground_z = 0 (相对NED系原点)
    t = (ground_z - cam_z) / r_ned.z
    目标世界 = cam_ned + t × r_ned
```

**当前简化**: `pixelToWorld()` 传入 `roll=0, pitch=0`，仅使用 yaw。在无人机基本水平时近似有效。

## 二、调试方法

### 2.1 映射误差来源

| 误差源 | 量级 | 如何确认 |
|--------|------|----------|
| roll/pitch 未补偿 | ~0.5-1.0m | 飞控日志中看姿态角，>5°即有影响 |
| 相机内参不准 | ~0.3-0.5m | `camera_calibration.py` 标定比较 fx/fy/cx/cy |
| yaw 误差 | 旋转误差 | heading 漂移或初始 yaw 未对齐 |
| 高度误差 | 线性缩放 | baro 精度 ~0.2m，影响 × 射影比 |
| 检测坐标抖动 | ~0.1m | YOLO 边界框噪声，Kalman 已滤波 |

### 2.2 验证方法

**A. 单点验证**: 悬停已知坐标上方，手动比较映射结果

```
# 在仿真中:
无人机悬停 (0, 30) NED, alt=3.5m, yaw=0
桶在 (0, 30) 正下方 → 像素应在 (320, 320)
如果桶在 (0, 31) → 像素应在 (320 + fy*1/3.5, 320) ≈ (320+158, 320)
```

**B. 批量验证**: 收集 SCAN 阶段所有 `[BOMB] Map:` 日志与已知世界坐标对比

**C. 反向验证**: 在已知世界坐标放置标记物，验证像素→世界→像素的往返误差

### 2.3 当前已知偏移

基于仿真测试日志与 SDF 世界文件对比：

| 桶 | 实际 NED | 映射 NED | 误差 |
|----|----------|----------|------|
| 桶1 (15cm) | (28.5, -1.2) | (28.69, -0.31) | N+0.2, E+0.9 ⚠️ |
| 桶2 (20cm) | (30.0, 1.0) | (30.30, 1.075) | N+0.3, E+0.07 ✅ |
| 桶3 (25cm) | (31.5, -0.3) | (31.85, -1.24) | N+0.35, E-0.94 ⚠️ |

桶1和桶3的 East 误差一致(~0.9m)，可能原因：无人机扫描时 roll 偏向一侧，或 EKF 原点偏移。

### 2.4 改进方向

1. **加入 roll/pitch**：从 `droneLink` 读取姿态角传入 `pixelToWorld()`
   ```cpp
   // 需要扩展 droneLink 公开 getRoll()/getPitch()/getYaw()
   double roll = link_.attitudeRoll();  // 需新增
   double pitch = link_.attitudePitch();
   ```
2. **相机标定**：使用 `calibrateCamera()` 获取精确内参
3. **多点平均**：同一簇映射 3-5 个不同帧取均值，减少单帧噪声
4. **扫描时小幅移动**：0.5m 半径微动增加视角多样性，减少单一视角系统误差

## 三、建图日志阅读指南

```
[0.2s] [BOMB] Map: 桶15cm @(28.69,-0.31) votes=3
         │       │         │              │
         │       │         └── 世界坐标     └── 投票数(众数bucketId得票)
         │       └── 桶类型(投票结果)
         └── 时间戳
```

`votes` 表示该簇被稳定跟踪期间，bucketId 的得票数。若 votes 较低（如 2），说明 YOLO 分类不稳定，但坐标仍可靠（来自簇中心）。
